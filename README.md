# バスデータ移行ツール

「駅すぱあと API」のバスデータ再編に伴い、利用者が保持する旧データを新データへ移行する作業を補助するコマンドラインツールです。新旧バス停対応表とAPIに互換性がある同種のデータ移行で再利用できます。

再編ごとの接続先と移行先データの適用開始日は、移行プロファイルで指定します。

本READMEはツールの使い方を説明します。ステータスの判定条件や差分の算出基準など、動作の詳細は [SPEC.md](./SPEC.md) を参照してください。

> [!NOTE]
> [2026年8月のバスデータ再編](https://docs.ekispert.com/data-migration-guide-202608/data-migration-guide/)の移行では、同梱の [profiles/bus-data-migration-202608.json](./profiles/bus-data-migration-202608.json) を指定して実行できます。具体的な作業手順はリンク先の移行手順書を参照してください。

## ツールの概要

| 機能                       | 対象データ               | 処理                                                            | 結果ファイル                                |
| -------------------------- | ------------------------ | --------------------------------------------------------------- | ------------------------------------------- |
| バス停データ変換           | バス停コード・バス停名称 | 新旧バス停対応表と照合して新コード・新名称を生成                | `変換結果-バスデータ.csv`                   |
| 経路シリアライズデータ移行 | 経路シリアライズデータ   | 旧経路を確認し、移行先APIで移行先候補を生成・動作確認           | `移行先経路候補-経路シリアライズデータ.csv` |
| 定期経路文字列移行         | 定期経路文字列           | バス停を変換し、移行先APIで新しい定期経路文字列を生成・動作確認 | `変換結果-定期経路文字列.csv`               |

> [!IMPORTANT]
> 本ツールは利用者のシステムへの結果反映を行いません。また、経路シリアライズデータの移行先を1つに自動確定しません。結果CSVの差分を確認し、採用する候補を選択してください。

## ツールを使う手順

### 1. 必要なものを用意する

| 必要なもの                       | 条件                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| Python                           | 3.11以上                                                        |
| 新旧バス停対応表                 | 対象の再編に対して配布されたCSV                                 |
| 移行したいデータ                 | 本READMEの形式で作成したCSV                                     |
| 移行プロファイル                 | APIを使う処理で必要。再編ごとの接続先・適用開始日を記載したJSON |
| 「駅すぱあと API」のアクセスキー | APIを使う処理で必要                                             |

ツール本体は、次のどちらかの方法で入手します。どちらの場合も、移行プロファイル（`profiles/`）と入力例（`examples/`）を含みます。

| 入手方法                 | 手順                                                                   |
| ------------------------ | ---------------------------------------------------------------------- |
| Releasesからダウンロード | [最新リリース](../../releases/latest)の `Source code (zip)` を展開する |
| Gitでクローン            | `git clone` でこのリポジトリを取得する                                 |

バス停データ変換は移行プロファイル・アクセスキー・ネットワーク接続なしで実行できます。

### 2. 入力CSVを作成する

結果を元データへ紐付けるため、すべての入力CSVに `id` 列を付けることを推奨します。`id` は移行処理には使用せず、結果CSVへそのまま出力します。省略した場合も処理できますが、結果CSVの `id` は空欄になり、特に複数ファイルや複数の移行先候補を扱う場合は、どの入力に対する結果か分かりづらくなります。

| 対象                   | 列                                                                                    | 必須列                                          |
| ---------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------- |
| バス停コード・名称     | `id`, `old_code`, `old_name`                                                          | `old_code`・`old_name` のいずれか               |
| 経路シリアライズデータ | `id`, `serialize_data`, `via_list`, `date`, `time`, `search_type`, `condition_detail` | `serialize_data`                                |
| 定期経路文字列         | `id`, `origin`, `destination`, `date`, `time`, `route_type`, `detail_route`           | `origin`, `destination`, `date`, `detail_route` |

バス停コードの入力例です。`id` には、入力データ内で重複しない管理番号などを指定します。

```csv
id,old_code
001,840901
004,840930
```

各列には次の値を指定します。

| 列                                   | 指定する値                                                                                                      |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `id`                                 | 結果との対応付けに使用する任意の識別子。指定を推奨。移行処理には使用しない                                      |
| `old_code` / `old_name`              | 移行前のバス停コードまたはバス停名称。両方を記載した場合は `old_code` で照合する                                |
| `serialize_data`                     | 移行前の経路シリアライズデータ（`Course/SerializeData`）                                                        |
| `via_list`                           | 元の探索で `viaList` に指定した経由駅を `:` で連結した値。元の探索条件を保持している場合は指定が必要          |
| `date` / `time`（経路シリアライズ）  | 元の探索で指定した日付・時刻（`YYYYMMDD` / `HHMM`）                                                             |
| `search_type` / `condition_detail`   | 元の探索で指定した `searchType` / `conditionDetail`                                                             |
| `origin` / `destination`（定期経路） | 定期区間の出発・到着駅として指定する、移行先APIで有効な駅コード                                             |
| `date` / `time`（定期経路）          | 移行先APIでの再探索・動作確認に使う日付・時刻（`YYYYMMDD` / `HHMM`）。`date` は移行プロファイルの適用開始日以降 |
| `route_type`                         | `assignDetailRoute`（方向あり）または `assignRoute`（方向なし）。省略時は `assignDetailRoute`                   |
| `detail_route`                       | 移行前の定期経路文字列                                                                                          |

バス停コードを保持していないデータは `old_name` に旧バス停名称を記載します。移行先を一意に決められるのは旧コードのため、旧コードを保持している場合は必ず `old_code` に記載してください。旧名称のみで照合した行は、対応表で移行先が1つに定まったことを意味します。同名の別バス停があり移行先が複数になる場合は変換せず `要確認（同名バス停あり）` とし、候補を `detail` 列に列挙します。

経路シリアライズデータの入力CSVには、移行後も使用するデータのみを記載します。

> [!IMPORTANT]
> 経路シリアライズデータと定期経路文字列では `date`・`time` の意味が異なります。1行に `serialize_data` と `detail_route` を同時に記載しないでください。

入力例は [station-input.csv](./examples/station-input.csv)、[serialize-input.csv](./examples/serialize-input.csv)、[teiki-input.csv](./examples/teiki-input.csv) にあります。`station-input.csv` は同じフォルダーの [mapping.csv](./examples/mapping.csv) を使って実行できます。`serialize-input.csv` と `teiki-input.csv` は、値を利用者のデータに置き換えて使うテンプレートです。3種類を1つにまとめる場合は [merged-input.csv](./examples/merged-input.csv) を参照してください。

### 3. 実行する

リポジトリのルートフォルダーで次を実行します。Releases のZIPを展開した場合、フォルダー名は `ekispert-api-bus-data-migration-tool-1.0.0` のようにバージョンが付きます。

```sh
cd ekispert-api-bus-data-migration-tool
python3 -m ekispert_bus_data_migration 移行したいデータ.csv
```

この実行方法は、移行プロファイルが不要なバス停データ変換で使用できます。Windowsで `python3` を使えない場合は `python` に読み替えます。

APIを使うデータがある場合は、対象再編の移行プロファイルを指定します。

```sh
python3 -m ekispert_bus_data_migration 移行したいデータ.csv --config profiles/bus-data-migration-202608.json
```

入力CSVが複数ある場合はまとめて指定できます。

```sh
python3 -m ekispert_bus_data_migration バス停.csv 経路.csv 定期.csv --config profiles/bus-data-migration-202608.json
```

結果CSVは、最初に指定した入力CSVと同じフォルダーに作成されます。

新旧バス停対応表は、入力CSVと同じフォルダーに置くと自動検出します。候補が複数見つかった場合は処理を開始せず、候補を画面に表示します。その場合は、使用する対応表を `--mapping` で指定してください。

```sh
python3 -m ekispert_bus_data_migration 入力.csv --mapping 新旧バス停対応表.csv
```

APIを使うデータがある場合は、必要になった時点でアクセスキーの入力を求めます。入力内容は画面に表示しません。

主なオプションは次のとおりです。

| オプション     | 内容                                                |
| -------------- | --------------------------------------------------- |
| `--mapping`    | 新旧バス停対応表CSVの明示指定                       |
| `--config`     | 再編ごとの移行プロファイルJSON                      |
| `--candidates` | 経路シリアライズデータの移行先候補数。既定3、最大20 |
| `--help`       | 使い方を表示                                        |

## 実行過程の例

次は3種類の入力CSVをまとめて処理した場合の簡略例です。

```text
$ python3 -m ekispert_bus_data_migration バス停.csv 経路.csv 定期.csv --config profiles/bus-data-migration-202608.json
=== バスデータ移行ツール ===

入力ファイル : バス停.csv(2件) 経路.csv(1件) 定期.csv(1件)
対応表       : 新旧バス停対応表.csv
検出データ   : バス停コード・名称(2件) / 経路シリアライズデータ(1件) / 定期経路文字列(1件)
移行プロファイル: bus-data-migration-202608

「駅すぱあと API」のアクセスキーが必要です。
アクセスキー:

バス停コード・名称
  結果: 変換済み:2

経路シリアライズデータ
  結果: 移行先の候補:1 （CSVは3行。1つの入力につき候補ごとに1行）

定期経路文字列
  結果: 変換済み:1

=== 処理が終わりました ===

作成したファイル:
  変換結果-バスデータ.csv
  移行先経路候補-経路シリアライズデータ.csv
  変換結果-定期経路文字列.csv
```

## 結果を確認する

結果CSVの `status` と `detail` を確認します。

| `status`                   | 対象機能                   | 意味                                                        |
| -------------------------- | -------------------------- | ----------------------------------------------------------- |
| `変換済み`                 | バス停データ変換           | 対応表との照合および新コード・新名称の生成に成功            |
| `変換済み`                 | 定期経路文字列移行         | 新しい定期経路文字列の生成および移行先APIでの動作確認に成功 |
| `移行先の候補`             | 経路シリアライズデータ移行 | 移行先APIで動作確認できた候補。採用する経路の選択が必要     |
| `対応表に該当なし`         | 全機能                     | 対応表に移行対象が無いため自動変換の対象外                  |
| `要確認（同名バス停あり）` | 全機能                     | 移行先を一意に決定できないため自動変換していない            |
| `更新不要`                 | 定期経路文字列移行         | 入力した定期経路文字列を移行先環境でそのまま利用可能        |
| `エラー`                   | 全機能                     | 処理を完了できなかった。理由は `detail` に出力              |

結果CSVの主な列は次のとおりです。入力した列は結果CSVにもそのまま出力するため、`エラー` の行だけを抜き出して再実行の入力に使えます。

| 列                               | 対象機能                   | 内容                                                               |
| -------------------------------- | -------------------------- | ------------------------------------------------------------------ |
| `status` / `detail`              | 全機能                     | 処理結果と、その理由                                               |
| `new_code` / `new_name`          | バス停データ変換           | 変換後のバス停コード・バス停名称                                   |
| `candidate_no`                   | 経路シリアライズデータ移行 | 移行先候補の番号。1つの入力に対し候補ごとに1行出力する             |
| `new_serialize_data`             | 経路シリアライズデータ移行 | 候補の新しい経路シリアライズデータ。動作確認まで完了した候補のみ   |
| `new_detail_route`               | 定期経路文字列移行         | 新しい定期経路文字列。動作確認まで完了した行のみ                   |
| `route_changed` / `fare_changed` | APIを使う2機能             | 移行前と比べて経路・運賃が変わったか（`変化あり` / `変化なし`）    |
| `old_route` / `new_route`        | APIを使う2機能             | 移行前後の経路を「駅名 →[路線名]→ 駅名」の形式に要約した文字列 |
| `old_fare` / `new_fare`          | 経路シリアライズデータ移行 | 移行前後の片道の運賃・料金の合計（円）                             |
| `old_time_min` / `new_time_min`  | 経路シリアライズデータ移行 | 移行前後の所要時間（分）                                           |

次も確認してください。

- 経路シリアライズデータ移行は1入力に対して候補ごとに1行出力するため、入力件数と結果行数が一致しない場合あり
- `route_changed`・`fare_changed` の `変化あり` は処理失敗ではなく、移行先候補を判断するための情報
- 画面の「要対応」に表示された未処理・エラーの有無
- 未処理または `エラー` がある場合は終了コードが `0` 以外

`route_changed`・`fare_changed` をどう判定しているか、各ステータスをどの条件で決めているかは [SPEC.md](./SPEC.md) の「2.3 ステータス・差分の値」および「3. 機能仕様」に記載しています。

## 最低限の注意事項

- 入力CSVと新旧バス停対応表はUTF-8。BOMの有無は不問。Excelでは「CSV UTF-8」で保存
- 結果CSVはUTF-8 BOM付き
- 同名の結果ファイルがある場合は、タイムスタンプ付きの名称に退避してから新しい結果を作成
- APIを使う処理は入力件数によって実行に時間がかかる場合あり
- 移行元APIは移行期間中だけ提供される場合あり。利用条件・提供終了時期は対象再編の案内を確認
- アクセスキーは実行時に画面から入力。自動実行では環境変数 `EKISPERT_ACCESS_KEY` を使用
